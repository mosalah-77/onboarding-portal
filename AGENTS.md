Use `docs/how-it-works.md` to follow the user workflow and `docs/code-graph.md` for graph commands. Refresh the local code graph after structural changes. Check source and tests before treating a graph edge as evidence.

Update the learner diagram, decisions and verification record with each completed workflow task. Mark unfinished behaviour as planned. Learning exercises must be labelled and explained; they do not replace product decisions or block routine implementation.

Keep this an independent synthetic portfolio demo. Do not copy code or assets from sibling client projects. AI-authored commits and documentation must say so.
